## 页面与入口

公开首页：`/quality/`，嵌入参数 `?embed=1` 继续有效。

公开页面包含「分组结果」「账号结果」「检测参考」；右上角提供「管理员配置」。
访客可以筛选公开分组、模型、时间范围、结果状态，查看通过率、有效样本数、请求故障和最近检测时间。
默认展示分组汇总，点击分组进入其账号结果；按账号查看时只使用公开展示名。

管理员入口继续使用 `/custom/quality-inspection`，由 code1024 自定义菜单传入管理员会话。
独立服务验证 active/admin 身份后显示「检测计划」「任务记录」「参数设置」「公开展示」。
从公开页点击管理员配置，跳转此入口；未登录时由 code1024 原登录流程处理，普通账号不能进入管理模式。
菜单的 view 参数只控制默认页面，不能作为权限依据。访客直接打开管理路由也必须通过服务端鉴权。

后续部署时可新增可见性为 user 的「模型质量」菜单，链接公开页；保留现有 admin 菜单。
code1024 对 user/admin 菜单分别筛选，不能只修改现有菜单的 visibility，否则管理员入口会消失。

## 按分组和按账号检测

每个检测计划包含名称、范围、检测配置、执行方式和公开设置。范围二选一：

1. 按分组：选择一个或多个分组，可以排除部分账号；执行前展开并展示账号清单。
2. 按账号：搜索并勾选一个或多个账号；选择分组可以辅助过滤账号列表，但不隐式扩大执行范围。

禁止用空选择代表全部账号。界面明确显示选中分组数、去重后的账号数、模型、检测项目和最大请求次数。
同一账号属于多个选中分组时，在同一任务内只测一次；组间复用必须满足模型、推理等级和检测版本一致。
不同计划可独立运行；相同账号的真实请求按队列协调，不重叠执行。

按分组检测在每次执行前重新解析成员；按账号检测固定账号 ID，缺失或不再满足条件时跳过并说明原因。
每次任务保存执行时成员快照，组成员后来变化不重写历史。
账号专测可以保持「不公开」，也可以明确关联到公开分组，或作为公开账号展示。
未选中的分组、账号和旧结果不因一次局部检测而删除。

“按分组”在第一版表示检测该分组内账号的上游表现，仍沿用直连账号适配器。
页面必须标注「账号直连检测」；该结果不能证明分组网关入口、路由与负载均衡链路正常。
真正通过分组网关发请求的「网关链路检测」需要专用网关 API Key 与独立计费/统计，后续可作为单独检测模式。

## 配置表单

### 管理员可编辑的业务配置

- 检测对象：分组/账号、排除项、停用计划。
- 平台与模型：协议、模型、推理等级；跨平台范围需分别指定模型和协议。
- 检测项目：逻辑题、SVG 生成；第一版沿用已有题库，不增加任意代码执行。
- 执行方式：手动、定时；时区、常规间隔、安静时段、安静时段间隔。
- 请求限制：总超时、空闲超时、最多尝试 1—3 次；每轮账号数和服务并发上限。
- 展示与评分：页面名称、公开分组/账号名称、评分权重、参考轮数、保留期限。
- 回写：页面默认关闭；部署侧未授权时不可开启，临时账号专测默认不回写。

表单提供保存前校验、执行对象预览与公开内容预览。
“保存配置”不会自动启动检测；“保存并检测”必须另外确认真实模型请求数量。
估算请求上限按检测项目与重试策略计算；价格缺失时显示未知，不显示零费用。

### 继续保留在部署文件中的基础配置

网关内部地址、身份验证地址、监听端口、数据目录、嵌入白名单、凭据文件路径、identity_salt、CA 路径和回写总开关。
这些字段在网页只显示连接状态，不开放任意 URL 或路径输入。
`config.json` 提供启动配置与初始默认值；业务配置持久化至独立服务自己的 SQLite，避免网页直接写只读挂载文件。

保存时增加配置版本，校验后事务提交；新任务读取新版本，在途任务继续使用启动时的配置快照。
并发编辑携带 revision，版本冲突返回明确提示，不能静默覆盖。
现有代码多处在 import 时读取配置，需改为显式配置快照传给 worker，不能只改 JSON 后声称热更新完成。

## 公开数据与统计

默认公开：公开展示名、平台/检测模型、检测方式、检测时间、样本数、逻辑题通过率、SVG 完整返回率、延迟、请求故障数、趋势。
默认不公开：真实账号名、邮箱、上游 ID、代理、凭据、供应倍率、内部优先级、服务配置、worker 日志和原始异常响应。
答案摘要和绘图作品由管理员单独选择公开。作品继续使用禁网 sandbox 与严格 CSP，不能执行模型代码获取站点数据。

分组指标按账号实际样本汇总，不直接平均账号百分比；同一组、同一结果只计一次。
没有样本显示「暂无检测数据」，结果过期显示「数据已过期」，不能当作通过或零分。
答题错误、请求故障、限额跳过、主动取消分别统计；综合分与逻辑题正确率分别显示。
不同模型、推理等级或题库版本分别统计，避免混在同一通过率里。
同一账号跨组出现时使用管理员指定别名，默认按组生成稳定公开名，不暴露内部关系。

公开与撤回以服务端发布记录为准；每次读取详情与作品链接也检查发布状态。
撤回后公开列表、详情、导出、作品入口均停止提供；无法收回访客此前已下载的数据。
第一版公开接口使用 no-store，避免撤回后残留可访问缓存。

## 服务内部职责

保留 Python、React、SQLite、现有适配器与 Docker 部署，不新增独立数据库、Redis 或微服务。

- Identity：验证宿主管理员会话；公开接口不读取或索取登录会话。
- Inventory：管理员同步完整可检测账号和分组，保持分组成员关系，不向公开页提供原始清单。
- Settings/Plans：校验、版本化业务参数，解析执行范围。
- Jobs：任务排队、范围快照、去重、任务进度、幂等启动与停止。
- Worker：按任务快照调用既有检测器和平台适配器。
- Publication：生成白名单字段的公开结果，并校验发布状态。
- Queries：分别返回管理员完整视图与访客公开视图。

SQLite 可增量增加 plans、jobs、job_targets、group_memberships、publications、settings_versions、audit_events。
现有 accounts/runs 数据迁移保留，新增任务关联与检测配置指纹，不能清库重建。
手动任务与定时任务都保存触发来源、操作者、配置版本、检测范围与结束原因。

## 自动运行凭据

手动任务可继续使用管理员当前短期会话，只在任务运行环境中传递，不持久化个人 JWT。
无人值守定时检测需要服务器机器凭据；未就绪时允许保存定时草稿，但禁止启用并显示具体原因。
不能通过保存浏览器 token 或管理员密码实现定时运行，不能自动降低 code1024 的二次认证策略。

## 改动规模与顺序

属于独立服务内的中等规模改造，需要调整权限、配置加载与任务模型；现有检测适配器、判题和视觉样式可复用。
第一阶段完成公开结果白名单投影、管理员身份区分、网页参数管理和按范围手动检测。
第二阶段完成计划定时、任务历史、重跑与配置版本；两阶段均保留现有实例数据并分步验收。
组网关链路检测、通知、完整基准题库和任意插件系统不在本轮核心范围。

## 验收条件

- 无登录、无 URL token、无服务口令，公开结果与公开详情可读取；未公开结果读取为 404。
- 匿名、普通账号不能同步、执行、保存或公开内容；管理员会话失效后不能继续管理。
- 按分组正确展开并去重，按账号只运行选中对象；部分范围检测不删除其他历史。
- 配置保存后新任务生效，在途任务不变；重启保留计划、设置、公开记录和历史。
- 隐藏账号与错误敏感信息，直接访问详情或作品不能绕过公开范围。
- 题目答错、请求故障、无数据、已过期四种状态显示正确；不同配置不混算。
- 首轮验收使用隔离模拟上游；生产验收先同步元数据，真实检测按明确范围执行。
- 维持 /quality/ 子路径、主题跟随、390px 手机布局，不修改或重启 code1024 程序。

## 设计依据

- `detector/session_auth.py` 当前只接受 active/admin，需要保留为管理权限边界，不能简单放开全局鉴权。
- `detector/server.py` 当前共用 state 投影含服务与成本信息，公开接口必须使用独立白名单投影。
- `detector/monitor.py:Store.sync` 把传入列表当完整账号集合，删除未出现账号及其历史；局部检测前必须拆分库存同步和任务筛选。
- `detector/monitor.py:collect` 以全局 last_completed_slot 去重，runs 唯一键为 account_id/slot/kind；独立计划需任务与检测配置维度。
- `detector/config.py` 及多个模块 import 时读取配置，网页保存需要配套 worker 配置快照机制。
- code1024 的既有 custom_menu_items 与 embedded-url 支持独立页面和管理员会话传递，公开页面无需传递会话。
