# code1024 独立质量巡检服务重设计

实现版本：v0.2.0。统一题库、账号与用户任务快照、真实分组时间轴、内容发布权限、机器凭据配置、持久化隔离/冷却复测均由独立服务实现。迁移不自动启用付费定时和账号调度修改。具体配置见 `code1024-standalone.md`。

目标：管理员统一管理题目，手动/定时检测指定账号；有明确失败证据时隔离账号，冷却后复测，通过才恢复。公开页按真实分组提供时间轴、模型切换、作品预览；登录用户使用自己的 Key 做相同题目的检测。

## 已确认故障

- 用户 Key API 应为 `GET /api/v1/keys` 和 `/api/v1/keys/:id`，原独立服务错误使用 `/api/v1/api-keys`。
- 用户接口必须只传宿主 JWT，不能被旧版独立控制台口令覆盖。
- 单个 Key 接口失败不能清空已经成功加载的题库和记录。HTML 响应必须转换成可定位的接口错误。
- 线上已归档错误：上游拒绝 `gpt-6.1-sol`。同一 Plus 账号、同一工作区使用 `0.154.0` 时模型清单无该模型，使用宿主当前版本 `0.169.0` 时有该模型。账号配置、access/id token 均为 Plus，工作区一致。因此需修复独立服务的旧客户端版本，不能据此认定套餐无权限；记录 `MODEL_UNSUPPORTED` 时不计答错，不自动降低调度能力，不对相同无效参数盲重试。

## 页面与视觉

继续使用系统中文无衬线字体，沿用主题变量：浅色背景 `#f8fafc`、面板 `#ffffff`、正文 `#0f172a`、次要文字 `#64748b`、主操作 `#0d9488`、故障 `#b91c1c`。深色沿用现有变量。左对齐，页面内容服务于检测记录，不增加装饰性指标。

公开页：按分组展示最近检测时间、通过/答错/请求故障、各模型状态和“查看检测记录”。详情左侧按时间选择一轮，右侧按模型和题目切换；显示开始/结束、耗时、题目版本、检测来源；支持沙箱作品预览、源码查看与复制。SVG 生成完整仅代表作品生成完成，画面好坏供用户比较。移动端时间轴移到内容上方。

管理页：检测计划、统一题库、调度策略与冷却账号、任务记录、公开展示。普通用户不显示管理入口，管理 API 仍在服务端验证角色。

自助检测：本人 Key → 可用模型 → 管理员已启用题目 → 执行 → 私有正文/作品。用户主动公开后，摘要与允许公开的作品同步到 Key 所属分组，明确标注“用户自测”，与“管理员账号巡检”分别统计。

## 执行与持久化

HTTP controller 只做鉴权、字段校验和投影；service 编排任务、快照和发布；question catalog 负责题目版本与判题；probe adapter 负责平台协议；routing policy 独立处理隔离与恢复；store 负责事务、幂等和审计。继续采用独立 Python 服务、React 页面、SQLite 持久化和 Nginx `/quality/` 转发，不修改 Sub2API。

所有任务保存题目内容、版本、期望值、模型、推理等级和来源快照。题库修改只影响新任务。原始 Key/宿主 JWT 不入库。机器凭据用于定时和服务重启后的复测；缺少凭据时明确显示“定时不可用”，手动仍可使用当前管理员会话。

题目类型：SVG/HTML 作品、数值/选择/JSON 标准答案、参考型指纹。内置鹈鹕骑自行车、糖果双次校验、逻辑选择、数值计算、JSON 遵循和指纹观察。指纹不依赖模型自报名称来认定真实身份，参考型题目不产生自动隔离结论。管理员可修改提示词与判题参数，版本由内容生成。

## 调度状态机

正常 → 达到连续失败阈值 → 隔离意图持久化 → Sub2API `schedulable=false` → 回读确认 → 冷却 → 到期账号直连复测（保持隔离）→ 全部策略题通过 → `schedulable=true` → 回读确认。

复测失败继续冷却；网络/鉴权/模型不支持单列；配置错误阻止自动质量判定。默认关闭自动回写，管理员配置阈值与冷却后再启用。隔离与恢复必须持有机器凭据，且计划、成员和账号状态仍满足范围。一个账号多个计划冲突时，任何有效失败策略仍保留隔离。

仅恢复本服务有隔离记录且回读确认的账号。账号被外部修改、移出范围、人工停用或达到网关限额时停止自动恢复，保留事件供管理员处理。Sub2API 布尔调度接口没有 CAS，恢复前后均核对更新时间和状态；有竞争时转人工处理，不宣称具备跨服务原子事务。保持每个分组最低可调度数量，防止巡检把整个分组清空。

用户 Key 请求经过正常网关调度，无法可靠知道实际命中了哪个上游账号。因此其结果可以进入对应分组的用户自测视图，但不能作为自动停用具体账号的依据。账号直连和网关检测的模型结果分别保留，不混成同一个通过率。

## 迁移与验收

保留旧配置、计划、结果和公开链接；新增表/列采用兼容迁移。升级前确认没有运行任务，备份 SQLite/作品卷和 Compose，保留原镜像。迁移默认不启用新定时、不发真实模型请求、不更改线上账号调度状态。

验收包括：真实 HTTP Key 契约、分组关联、题库快照、普通用户权限、公开撤回、沙箱作品隔离、400 分类、冷却重启恢复、回写失败及不确定回执、外部账号变更、最后可用账号保护。用本地模拟网关验证这些路径，真实线上仅做无收费请求的页面与接口验证。
