# 分组巡检与 Key 检测

独立服务保留分组定时巡检和本人 Key 检测两个入口。v0.3.3 新增按分组配置的可选自动剔除；默认关闭。不修改 code1024 源码。

## 定时巡检

管理员通过「巡检设置」进入独立的管理员页面，该页面只显示设置和「返回公开页」，不展示公开结果、检测入口或刷新按钮。普通用户不会看到设置入口；管理接口仍要求有效管理员登录。管理员为一个分组保存模型、思考强度、题目和白天运行时间。每轮在该分组内选取最近使用的一个账号；账号必须 active、schedulable=true、有有效 last_used_at，且没有过期、限流或临时暂停。候选不足时跳过，不改用其他分组或没有使用记录的账号。真实请求发出前再次验证分组和可调度状态。预览与执行采用题目和配置快照。

配置示例：Plus 分组，gpt-6.1-sol，low，Asia/Shanghai，白天间隔 60 分钟，22:00–09:00 暂停。每天 09:00、10:00……21:00 共 13 轮；夜间重启不补跑，排队任务在进入夜间后也不新发起请求。已发出的请求可以等待完成。相同计划同一时间槽最多排队一次，编辑配置不额外补跑该时间槽。

鹈鹕题目：`创建一个HTML，内容是SVG绘制一只鹈鹕骑自行车的2D动画`。

## Key 检测

用户登录 code1024 后，选择本人 Key、题目、模型和思考强度。请求经普通网关模型接口执行，遵循原 Key 的分组、计费与额度；不使用管理员机器 Key 调用模型。原始 Key 和登录 JWT 不持久化到任务。回答默认私有，用户主动公开后才出现在 Key 所属分组，可随时撤回。

## 展示与判定

结果页显示分组、检测轮次、模型、来源、耗时和题目。鹈鹕 HTML/SVG 通过独立作品接口与 opaque sandbox 渲染，允许内联脚本支持动画，但禁止联网、同源权限、表单与顶层导航。支持停止/重播、源码和复制。固定答案题展示原回答、识别答案、标准答案及通过/未通过/无法判定；指纹类只供参考；请求失败单独记录。

普通接口不返回账号 ID、账号名、用户 ID 或原始凭据。管理员历史接口在宿主管理员会话验证后返回巡检账号。私有作品使用本人会话生成十分钟签名链接。登录可见模式下，公开作品和私有作品的 iframe 均使用十分钟、仅限指定作品路径的随机预览凭证；服务端在每次访问作品时重新验证宿主登录状态，私有作品还会核对所有者。凭证仅保存在服务内存，容量最多 1024 条，过期或重启后需重新加载记录；用户 JWT 不会进入 iframe URL。

## 结果访问权限（v0.3.2）

管理员进入「巡检设置 → 结果访问权限」，配置「允许匿名查看结果」并单独保存。该开关作用于全部分组，默认关闭；旧 volume 升级时新增默认关闭的配置，不改变已有巡检、题目、凭据和历史。

- 关闭：全部 `/api/public/*` 结果、历史、回答和作品 API 必须验证有效的 code1024 登录。嵌入页沿用宿主会话；直接打开而未携带有效会话时只显示登录提示，不返回检测数据。
- 开启：访客可匿名查看已发布的分组结果、用户主动共享的结果和公开作品；不提供账号信息。
- 私有作品始终要求有效的本人登录；开启匿名也不会公开私有作品。巡检设置始终仅管理员可用，Key 检测始终要求本人登录。
- 管理 API：`GET /api/admin/access` 返回 `{revision, value: {allow_anonymous_results: false}}`，`PUT /api/admin/access` 提交相同结构；必须是真正的 JSON 布尔值，并通过 revision 检查并发更新，修改记录写入审计。

访问权限是独立服务的数据库配置，无需修改 Sub2API、Nginx 或 `config.json`。静态页面外壳可加载；受保护的是所有检测数据和作品。iframe 是否嵌入、Referer 和 URL 中的用户 ID 都不作为登录凭据。

## 机器凭据

专用 scoped admin Key 仅授予目标分组的 `accounts.read` 和 `groups.list.read`，限制平台和账号类型，不授予全权访问或任何写权限。密钥由管理员界面验证后保存于 `/data/private/automation-key`，权限 0600。

当前网关的受限 Key 不能读取账号令牌。宿主服务器用原管理员授权流程运行 `scripts/export_account_snapshot.py`，仅导出指定分组，保存在受保护文件。配置 `SUB2API_ACCOUNT_SNAPSHOT_FILE=/run/secrets/plus-account-snapshot.json`。脚本保留原二次验证边界，遇到 403 立即停止，绝不关闭保护。不要将管理员登录文件挂载到服务容器。

快照应每两分钟刷新，包括 OAuth 当前凭据、代理、实际分组、最近使用时间和配额策略。读取时验证账号身份、授权分组以及十分钟有效期；缺失、过期或身份不符时停止模型请求。账号 OAuth 刷新仍由网关负责。

宿主 systemd timer 只同步私有快照，实际模型请求由服务内部按每个分组的计划触发。凭据同步持续运行不代表夜间会调用模型。

## 升级与回滚

先停止新任务并备份 volume、config.json、compose.yaml，再升级独立服务。旧隔离表仅保留用于历史审计和回滚，v0.3.0 不再读取或执行；迁移去掉计划的隔离与回写开关，不修改网关账号状态。已有结果和原题目快照保留到保留期限。

管理 API 入口为 `/api/admin/inspections`，按分组保存，不再暴露原多模块控制台。生产 URL 可继续沿用 `/quality/` 与 code1024 自定义嵌入页面。


## 多题巡检和自动剔除（v0.3.3）

「巡检设置」可多选题目，每题独立配置题目内容、标准答案和每轮请求次数（1–3 次）。同轮各题检测同一个账号；糖果测试默认改为一次请求。升级仅迁移未定制的旧“糖果双次校验”默认配置，已完成任务和题目快照保持原样，定制题不自动覆盖。

每个分组新增独立配置：

```json
{"quarantine":{"enabled":false,"cooldown_minutes":60,"hide_failed_results":true}}
```

- `enabled`：自动剔除，默认关闭。仅支持至少选择一道启用的数值、选择或 JSON 标准答案题的单分组计划。
- `cooldown_minutes`：冷却时间，5–10080 分钟。修改影响后续重新计算的冷却，已保存的到期时间不提前重算。
- `hide_failed_results`：开启剔除的巡检中，隐藏明确答错账号本轮的全部结果，包括同轮鹈鹕作品。默认开启；开关修改后对该计划既有记录即时生效。历史、统计、回答、作品接口统一过滤，不删除原数据；管理员历史、详情和作品仍可查看。关闭剔除不自动公开之前隐藏的失败记录，需要单独关闭隐藏开关。用户自己 Key 的公开结果不受该策略影响。

一轮完成后，只要任意一道标准答案题中有可重新核验的明确错误答案，即可剔除；其他题目的未知、请求错误或未完成回答不会抹去已确认的错误。鹈鹕结构判断、指纹观察、无明确答案、请求错误、超时或额度不足本身均不能触发剔除。用户 Key 检测从不触发账号调度修改。

剔除仅调用网关账号的 `schedulable=false`，不删除账号，不修改 status、优先级或凭据。账号调度开关对该账号所属的所有分组生效。服务写入前核对身份、完整分组、启用状态、配额及其他暂停信息，写入后回读确认；已经人工禁用的账号不接管。

冷却到期后，在不可调度状态下直接检测原账号，使用触发剔除时冻结的全部标准答案题、模型和思考强度，不先恢复调度。全部复测通过且证据仍在有效冷却窗口内，才恢复 `schedulable=true`；失败、未知或请求错误继续冷却。复测同样遵守当前计划的夜间暂停时间。

关闭剔除或停用分组计划，会取消后续复测并停止自动操作，已经剔除的账号不会因此自动恢复；重新启用后继续处理，或使用「停止托管（保持当前调度状态）」后到网关人工处理。权限不足、身份/分组变化或写入多次无法确认会显示需要管理员处理。状态、写入意图、复测任务和审计持久化，重启不会把账号先恢复。网关调度 API 无版本比较能力，外部并发修改不能获得强所有权保证；人工处理前应先停止托管。

自动剔除需要单独的受限管理员 Key，最小权限 `accounts.read`、`accounts.status`（如需要读取分组，再授予 `groups.list.read`），仅授权目标分组、平台和账号类型。不扩权原只读巡检 Key。管理员可在「自动剔除管理」保存，文件位于 `/data/private/quarantine-key`，权限 0600，不回显。保存仅验证读取权限，不通过真实修改账号来试写；实际权限不足会明确记录 403 并停止自动处理该账号。

新增 API 均只允许管理员登录并校验写入来源：`PUT /api/admin/quarantine-key`、`GET /api/admin/quarantines`、`POST /api/admin/quarantines/:account_id/handover`。管理员可通过 `/api/admin/records/:id` 和对应 `/artifact` 查看隐藏结果；作品仍使用受限 sandbox 和短期预览凭证，普通用户不能访问。

本次数据库变更只新增 `inspection_quarantine` 表和糖果默认值迁移标记，保留旧隔离表但不复用其语义。首次升级时没有托管记录，旧计划默认关闭剔除。回滚前需先停用策略、处理已被剔除的真实账号并备份数据；旧版本不会自动恢复新版本剔除的账号。


## 调度权限与权限修复（v0.3.4）

Sub2API 的 `schedulable` 字段和 `/accounts/:id/schedulable` 接口要求 `accounts.status`，`accounts.schedule` 只控制并发、优先级及有效期。专用剔除 Key 应授予 `accounts.read`、`accounts.status`，按需增加 `groups.list.read`；不需要 `accounts.schedule`。服务仍只写 `schedulable`，不修改账号 status。

遇到 403 时，模型测试仍保留其真实判定，账号托管记录进入“需要管理员处理”，不会把回写失败伪装成成功剔除。修复 Key 后，可在管理页点击“修复后核验并重试”（`POST /api/admin/quarantines/:account_id/retry`）；不会重新请求模型，而是检查策略、账号身份、证据完整性与有效期，再尝试原调度操作。剔除重试要求当前标准答案题与原证据一致；恢复重试要求原复测通过。旧证据超过当前冷却时长、题目已变化、策略已关闭或账号已转人工时拒绝写入。
