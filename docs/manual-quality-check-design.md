# 本人 Key 自助选题检测、公开结果与 400 问题设计

状态：设计方案与线上问题调查已完成，新增功能尚未实现或部署。
以用户最新补充为准：所有登录用户，包括管理员，都能使用本人 code1024 API Key 手动选题检测；
普通用户和匿名访客不显示“管理员配置”。本方案只修改独立 ai-drool-router 服务。

## 1. 权限与检测方式

| 能力 | 匿名访客 | 普通登录用户 | 管理员 |
| --- | --- | --- | --- |
| 查看已公开结果 | 可以 | 可以 | 可以 |
| 使用本人 Key 选题检测 | 登录后可用 | 可以 | 可以，同样使用本人 Key |
| 查看本人全部任务与完整结果 | 登录后可用 | 可以 | 可以 |
| 发布或撤回本人任务摘要 | 不可以 | 可以 | 可以 |
| 管理员配置按钮 | 隐藏 | 隐藏 | 验证 active/admin 后显示 |
| 管理题目目录、全局限制、公开内容 | 不可以 | 不可以 | 可以 |
| 现有上游账号/分组直连巡检 | 不可以 | 不可以 | 保留在管理员控制台 |

两种检测明确区分：

- 用户自测：本人平台 Key → code1024 网关 → 网关调度上游，消耗本人余额、订阅或 Key 配额。
- 平台巡检：沿用管理员对上游账号/分组的直连检测，结果标明“账号直连”，按已有规则处理凭据。

管理员在“自助检测”中也使用本人平台 Key，不隐式使用管理员凭据或免费额度。
普通用户不选择、导出或遍历上游账号。选择分组通过本人 Key 的绑定实现，不能越过 Key 权限指定分组。
两种来源的结果分开汇总，避免将网关请求当成某个指定上游账号的检测证据。

## 2. 现有能力与需要补齐的部分

现有独立服务可以复用：管理员认证、计划配置、账号/分组解析、范围预览、排队、幂等、停止、
SQLite 归档、公开白名单、主题和嵌入布局。现有任务使用管理员能力读取上游凭据再直连，不能直接开放给普通用户。

主项目已有用户接口可以支持本人 Key 模式：

- `GET /api/v1/auth/me`：验证登录身份。
- `GET /api/v1/keys`：按当前登录用户返回自己的 Key。
- `GET /api/v1/keys/:id`：读取时校验 Key 所有权，不属于当前用户则拒绝。
- 网关 `/v1/models` 及对应生成接口：按 Key 的模型权限、分组、路由和正常计费处理请求。

依据：主项目 `backend/internal/handler/api_key_handler.go`、`backend/internal/server/routes/user.go`、
`gateway.go` 与 `frontend/src/api/keys.ts`；独立服务 `console_api.py`、`console_service.py`、
`console_store.py`、`console_public.py`、`question_bank.py`、`monitor.py` 和 `web/src/console.jsx`。

当前“逻辑双题”实际是同一道原始糖果题连续两次独立请求；“检测参考”里的 JSON、长上下文、代码示例尚非可执行题库。
判题函数虽然支持部分数值、选择和 JSON，执行器仍锁定原糖果题，需要增加真正的通用选题执行流程。

## 3. 页面与操作流程

普通页面：**公开结果 / 自助检测 / 我的记录 / 检测参考**。
匿名访客可读公开内容，进入自助检测或个人记录时提示登录 code1024；无须为独立服务单独注册。
管理员额外看到“管理员配置”，进入既有后台管理题目、全局限制、平台巡检和公开内容。

“管理员配置”仅在本服务验证 active/admin 成功后显示。普通身份、未登录、身份校验中、会话过期时均隐藏，
不依据 `view=admin` 或浏览器缓存角色显示。管理员仍可通过 code1024 左侧“质量巡检”菜单进入。

```text
模型质量巡检
公开结果 | 自助检测 | 我的记录 | 检测参考      [管理员配置，仅管理员]

自助检测                                    本次预览
① 选择我的 Key                              Key 名称与脱敏标识
   名称 / 所属分组 / 状态                     分组与计费说明
② 选择模型、协议与推理等级                     模型、题目、轮数
③ 勾选测试题目                              正常请求数 / 含重试上限
   糖果双次 / 逻辑 / 数值 / JSON / SVG         结果发布范围
   查看题目和判分规则                         [预览]
④ 每题重复轮数，默认 1                        [确认并开始检测]
⑤ [✓] 完成后公开结果摘要
   [ ] 公开回答正文  [ ] 公开作品
```

有一个可用 Key 时可默认选中；有多个时由用户选择，或恢复本人上次选择并重新校验。
没有可用 Key 时链接到现有“API 密钥”页面，不自动创建、改绑 Key 或调整额度。
允许按分组筛选自己的 Key，所属分组只读；第一版每任务使用一个 Key，多分组通过不同 Key 分别测试。

选择 Key 后读取其模型列表；列表加载失败时明确提示，不填虚构默认模型。模型列表代表网关声明的可用目录，
不保证上游实时支持。协议与参数遵循网关现有能力，不自动切换模型或降级推理等级。
模型调用使用统一的自测客户端身份，不伪装成官方 CLI 来绕过分组限制；仅允许特定客户端的分组明确提示不适用。

预览不调用生成接口。确认页明确显示 Key、分组、模型、题目、请求数、计费归属与公开选项。
提交后进入任务详情；刷新页面从“我的记录”继续查看，不重复创建任务。手机按同一顺序单列排列。

## 4. 身份、Key 与网关请求

推荐由独立服务作为中间层。浏览器仅提交本人 Key ID；服务以用户会话读取本人 Key，再发送网关请求。
返回浏览器的 Key 清单只保留 ID、名称、脱敏标识、分组、状态和必要的额度说明，不转发原始 Key 字段。

服务端先验证 active 用户，读取并确认 Key 所有权、状态和绑定，再生成执行预览。
`owner_user_id` 来自服务端验证结果，不能使用 URL 的 `user_id` 或客户端传入的 owner 作为身份依据。
预览凭据绑定用户、Key ID、分组、模型、题目版本、参数与配置版本，短期有效；执行前再次校验，变化后要求重新预览。

登录会话负责身份和所有权验证，平台 Key 负责生成请求，两者用途分开。
JWT 和 Key 原文只在内存短期使用，不写 SQLite、任务快照、URL、应用日志、浏览器持久存储或导出文件。
任务结束后释放凭据。重启后的排队/运行任务标记中断，由本人重新确认，不保存个人凭据实现自动补跑。
Key 撤销、过期、额度不足或重新校验失败时显示原因，不改用管理员 Key。

网关目标固定为部署配置，不接受普通用户的任意地址、代理、请求头或上游账号 ID。
沿用网关模型权限、余额/订阅扣费、Key 配额、并发和请求限制，不修改主项目账务。
IP 白名单等按现有网关信任链执行；上线前验证独立服务请求来源与客户端 IP 传递，不伪造来源绕过限制。

## 5. 第一版题目目录与执行规则

| 测试项目 | 判定方式 | 本次处理 |
| --- | --- | --- |
| 原始糖果双次校验 | 两次独立请求均正确；首次明确答错结束该项目 | 保留原规则，展示首答与复核 |
| 逻辑选择题 | 按明确标准选项判定 | 增加经过校验的内置短题 |
| 数值计算题 | 按明确标准数值、单位与输出契约判定 | 增加经过校验的内置短题 |
| JSON 指令遵循 | 严格解析，分别检查结构与内容 | 接入经过校验的参考短题 |
| SVG 动画题 | 完整 HTML/SVG 与隔离作品预览 | 保留，并标注完整性不等于画面质量 |

题目含稳定 ID、题目版本、判分版本、题干、输出约束、来源与请求阶段。任务保存完整快照，题库升级不改变旧结果。
第一版提供内置多选题目和“轻量 / 逻辑与格式 / 含 SVG”预设组合，启动前展开实际题目。
自定义题库、长上下文参数化生成、人工评分和代码执行基准分别放后续，不把参考步骤宣称为已有自动评测。

- 每题默认一轮，重复次数受限；独立上下文，不携带上一题答案。
- 某题答错后继续其他已选题目；糖果项目内部保留首次答错结束规则。
- 正常答案不因答错而自动重新问到答对。格式是测试目标时记录格式失败；无法可靠提取普通答案时记为无法判定。
- 答对、答错、无法判定、请求故障、限额跳过、取消分开记录，未完成不等于答错。
- 截断响应不判完整成功；SVG 完整率与客观题正确率分开展示。
- 预览按 Key 数、题目阶段、轮数和重试策略计算正常请求数及最大请求数；第一版每任务一个 Key。
- 费用缺少可靠依据时显示未知；实际费用以 code1024 使用记录为准，不使用余额差额猜测本任务费用。

建议默认每用户一个运行任务，限制排队数、题目数、轮数、输出上限和全局并发；用户任务公平排队。
幂等键防止重复提交，但不宣称网关请求天然具有幂等性。已发送后结果未知的请求单独标记，避免盲目自动重发。

## 6. 我的记录与公开展示

“我的记录”显示本人全部任务、题目、判分依据、响应、耗时、用量与脱敏错误；其他用户不能读取私有任务。
每个任务的详情为“Key 脱敏标识 × 模型 × 题目 × 轮次”，糖果项目补充两阶段，SVG 展示隔离作品。
生命周期与结果分开：执行结束不等于通过，页面同时显示成功、答错、无法判定和故障数。

为满足其他用户能看到结果，建议默认勾选“完成后公开结果摘要”，用户可关闭，确认页再次展示该选择。
回答正文与作品分别授权，默认不公开；本人可发布/撤回，管理员可下架公开内容，操作保留审计。
默认公开不包含用户名、邮箱、Key 原文/尾号/名称、Key ID、内部上游账号、私有分组名及原始错误。
公开分组标签由管理员允许发布的名称映射生成；没有公开映射时使用通用标签，不能直接泄露用户专属分组。

公开页展示两类来源：

- 平台巡检：原有管理员账号/分组证据。
- 用户自测：经服务端调用网关并判定的公开批次，展示公开模型、题目、时间、样本量、状态和耗时。

第一版“用户自测”以单次批次结果为主，不把自选题、自选 Key、只发布部分任务的数据直接混进平台通过率或排名。
公开批次使用不可猜测的公共 ID，提供不带登录 token 的分享链接；每次访问列表、详情和作品均检查发布状态。
撤回后这些入口同时停止提供，不影响私有历史。公开结果继续无需登录，个人任务与执行必须登录。

统计只比较相同题目版本、判分规则、模型、协议、推理等级、输出预算和重复规则。
客观题正确率 = 答对 /（答对 + 答错），旁列无法判定、故障和限额数。糖果显示项目通过率，JSON 显示格式/内容，
SVG 显示完整率；第一版不生成混合的“智力总分”。实际响应模型如果上游未提供，显示未知，不凭自报证明模型身份。

## 7. 服务器 HTTP 400 调查

调查日期：北京时间 2026-11-17。只读取已有任务、运行库、配置快照及账号元数据，没有新增生成请求或改动生产配置。

任务 `bc4b4c0465b84400a197c15455a7c846` 于 2026-11-17 08:49:11 开始，08:49:37 结束：

- 4 个 OpenAI OAuth 账号，检测 `candy` 与 `drawing` 共 8 项。
- 模型快照 `gpt-6.1-sol`，协议 `openai_responses`，推理等级 `low`。
- 8 项均为 `error / HTTP_400`，各 2 次尝试，共记录 16 次 HTTP 尝试，糖果项未进入第二阶段。
- 上游一致返回：`The 'gpt-6.1-sol' model is not supported when using Codex with a ChatGPT account.`
- 数据库任务状态为 `completed`，因为 worker 正常退出，而非实际答题通过。
- 当前 4 个账号元数据均为 OAuth，对该模型的精确映射仍是同名映射；配置中出现模型不代表上游已开放。

当前适配器 `upstream.py:_openai_oauth_request` 直接向 ChatGPT Codex Responses 接口发送所配置的模型名。
因此本次 400 的直接原因是该请求组合被上游以模型不支持拒绝，不是题目答案错误或自定义页面 404。
未查询官方实时支持目录或作新的生成验证，不能据此断言账号永不支持该模型，也不能保证换某个名字一定成功。
直连适配器与正常网关还存在模型映射、参数处理和客户端身份差异，不能认为两条调用路径效果完全等价。

本次设计纳入以下处理：

1. 自助任务通过本人 Key 走网关，不导出 OAuth 凭据、不直接进入账号直连路径。网关仍可能返回模型不支持，必须显示实际错误。
2. 选择模型时读取该 Key 的模型目录，标明目录来源和“未实测”状态，不把目录当作实时成功保证。
3. 请求兼容层按协议构造参数；模型、推理等级、输出上限的不支持都需明确分类，不静默删除参数或替换模型。
4. 已确认模型不支持/参数无效的 HTTP 400 不重复重试。同一任务 Key/模型/协议组合再次命中相同条件的项目跳过，保留失败原因。
5. 401、403、额度不足等按实际错误停止相关调用；429/暂态错误按限额与有界策略处理，不能所有异常一律重发。
6. 用户显示“模型暂不支持，未获得可判定答案”；管理员看到脱敏的原始错误、阶段、协议、模型和可用关联 ID。
7. 全部请求被拒绝时显示“执行结束：0 项可判定，8 项请求故障”，或“执行失败：模型不支持”，不只显示“已完成”。
8. 这类故障不计入答题错误率，不显示为降智、不改变账号调度状态。已有记录保留真实错误，不能改写成成功。

建议报错格式包含阶段、稳定错误码、是否可重试、脱敏说明和建议动作。
例如 `stage=gateway_request / code=MODEL_UNSUPPORTED / retryable=false`；普通用户不返回内部账号和凭据。
若仍需修复原直连巡检，应核对当时账号支持目录、有效客户端协议与真实请求，再选择兼容模型；本轮不盲目改名或重跑收费请求。

## 8. 实现结构与增量数据

不增加微服务或数据库，保留 Python、React、SQLite 与 Docker。复用现有队列基础，新增用户认证、网关执行和本人任务边界。

```text
用户会话 → 本人 Key 元数据 → 选模型与题目 → 零调用预览 → 确认
                                                         ↓
                                          服务端校验 → 任务队列
                                                         ↓
                                          本人 Key 调用 code1024 网关
                                                         ↓
                                       判分与归档 → 我的记录 → 公开摘要
```

职责划分：

- Identity：验证 active 用户，管理操作额外要求 admin；保留现有 admin API 的权限，不通过放宽全局鉴权开放任务。
- UserKeys：以本人会话读取 Key，仅返回脱敏元数据，在执行时短暂获取请求凭据。
- QuestionCatalog：内置题目、版本、阶段与判分规则；所有任务使用相同目录和判分器。
- ExecutionSpec：统一校验 Key、模型、选题、轮数、预算、预览与快照。
- Jobs：所有权、幂等、公平排队、取消与恢复。用户执行器仅调用网关，平台巡检保留独立适配器。
- Results：逐题/逐轮记录。自测任务仅本人可读，公开内容经过独立白名单投影。
- Publication：本人发布/撤回、管理员下架，独立于不可变的执行证据。

任务增量字段包括 owner、execution_mode（user_gateway / admin_direct）、来源、Key ID/绑定快照、规格版本和发布策略。
Key ID 等内部字段仅作所有权与审计使用，禁止进入公共投影；快照不含任何凭据。
结果增加题目版本、判分版本、轮次/阶段、错误分类、请求模型及实际返回模型、用量和必要的关联 ID。
临时自测任务不强制关联长期计划，不为每次检测自动创建计划；旧管理员计划、旧糖果和 SVG 历史兼容保留。

拟新增用户接口：

```text
GET  /api/user/me
GET  /api/user/keys
GET  /api/user/keys/:id/models
GET  /api/user/questions
POST /api/user/executions/preview
GET/POST /api/user/jobs
GET  /api/user/jobs/:id
POST /api/user/jobs/:id/stop
PUT  /api/user/jobs/:id/publication
GET  /api/public/batches
GET  /api/public/batches/:publicId
```

所有 user 写接口验证登录、来源、JSON、请求大小与所有权。未知任务和非本人任务统一拒绝，不能只靠前端隐藏。
公共接口不接收 Key、不提供执行能力；现有管理员接口继续要求管理员，普通用户无权读取平台账号清单。

## 9. 实施顺序与验收

第一阶段：落实管理员按钮可见性，增加错误分类与任务结果说明，补充现有 400 的脱敏诊断。
第二阶段：完成本人 Key 选择、网关选题执行、预览确认、个人任务与逐题结果；内置首批客观题。
第三阶段：本人结果公开/撤回、匿名批次详情、来源区分与浏览器验收，统一部署独立服务。
本方案是独立服务内的中等改造，权限、凭据边界和通用执行器是主要工作。

至少验证：

- 普通用户及匿名访客不出现管理按钮；管理员验证成功后可进入管理，会话过期后入口消失。
- 用户 A 不能列出/执行用户 B 的 Key，也不能查看、停止或发布 B 的私有任务；管理员自测同样用本人 Key。
- Key、分组、模型、题目和轮数确实进入请求；预览零生成请求，重复提交只建一项任务。
- 全部网关调用使用所选本人 Key，限额/鉴权失败不自动换 Key，任务快照和日志无凭据。
- 使用此次模型不支持 400 的模拟响应回归：不重复请求、不判答错、无虚假通过、全故障任务明确提示。
- 答错继续其他题，糖果保留两阶段语义，JSON、SVG 与故障统计分开，截断和无法判定如实呈现。
- 仅公开授权字段，撤回阻断公开列表/批次/详情/作品；公开 URL 不带登录 token。
- 旧计划/历史与新自测分别可查，题库与组成员变更不改写历史；重启保留记录且不自动重发。
- `/quality/` 子路径、宿主嵌入、主题与 390px 布局通过实际浏览器检查。

开发验收使用隔离模拟上游。生产验证先使用身份、Key 元数据与模型目录等只读接口；真实生成验收需明确 Key、题目与调用范围。
上线备份独立服务 SQLite 和数据卷，只升级该服务；回滚使用兼容程序/数据或对应备份，不清空历史、不修改 code1024 主库。

## 10. 外挂菜单的一级分组

截图中的“系统 / 自定义 / 我的账户”由 code1024 前端的 `useShellNav` 生成，外挂服务只提供页面地址和菜单项，
不能从 `/quality/` 或 `config.json` 改宿主侧边栏。当前 `custom_menu_items` 只有菜单项字段，所有外挂项会统一放在“自定义”一级下。
因此当前版本可以调整外挂项的名称、图标和同一“自定义”组内顺序，但不能仅靠服务配置：

- 重命名“自定义”一级；
- 把质量巡检挂到“系统”或“我的账户”；
- 创建任意新的一级分组。

这属于 code1024 前端导航能力，需要修改主项目的菜单数据结构和 `useShellNav`，与独立巡检服务无关。

### 推荐的两级实现

先做“挂载到现有一级”，改动较小。给 `CustomMenuItem` 增加可选字段：

```json
{
  "id": "quality-results",
  "label": "模型质量",
  "url": "https://api.code1024.cc/quality/?embed=1",
  "visibility": "user",
  "sort_order": 20,
  "section_key": "custom"
}
```

`section_key` 只允许宿主已有稳定键，普通用户可用 `workspace / resources / account / custom`，
管理员可用 `overview / people / infra / commerce / system / custom / personal`。未知键回退到 `custom`，
避免升级后菜单消失。前端按 section_key 将菜单项合并到对应一级，后端同步校验并在公开设置中保留该字段。
这样可以把“模型质量”放入“我的账户”或管理员“系统”，而不改变一级名称。

再做“自定义一级名称”。增加独立配置数组，避免把一级标题重复存到每个菜单项：

```json
{
  "id": "quality-tools",
  "label": "模型质量",
  "visibility": "user",
  "sort_order": 20,
  "section_key": "quality-tools"
}
```

配套 `custom_menu_sections`：

```json
{
  "id": "quality-tools",
  "label": "质量工具",
  "visibility": "user",
  "sort_order": 30
}
```

一级配置需要独立的 ID、显示名、可见性和排序；前端没有子项时不显示空一级，移动端和收起侧栏显示分隔线或标题。
删除或改名一级只影响导航标签，不改变 `/custom/:id` 路由和外部服务地址。

### 对当前质量巡检的推荐落点

- 普通用户的“模型质量”建议先挂在“我的账户”，因为自助检测使用本人 Key，和 API 密钥、使用记录属于同一用户功能区。
- 管理员的“质量巡检”建议挂在“系统”，因为它包含平台巡检、全局参数、公开管理和任务运维。
- 如果希望视觉上保持独立，再建立自定义一级“质量工具”，同时放入普通用户的自助检测和管理员的质量巡检；同名一级需按可见性分别配置，避免普通用户看到管理员入口。

### 改动范围与边界

只支持挂载现有一级时，需要修改 code1024 的 Go DTO/设置校验、TypeScript 类型、`useShellNav` 分组逻辑、管理员设置页面和前端测试，
属于小到中等改动；独立巡检服务的页面和接口无需改。支持自定义一级时还要增加一级配置编辑、公开设置过滤、权限校验、删除回退和迁移测试，属于中等改动。
生产上应先备份 `custom_menu_items`，新增字段采用可选兼容方式，读不到或无效时统一回退到“自定义”。
